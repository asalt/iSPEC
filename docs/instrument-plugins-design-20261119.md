# Instrument monitoring: one plugin, two places to run it

**Phase 1 approved and exercised; phases 2 and 3 remain proposals.** Build two read-only collectors against real sources first: `thermo` on Eclipse and `bruker` on tims-ultra. Let each own its tables. Standardize only what staff need to see across instruments and what a disconnected PC must deliver reliably. No instrument commands, RAW copies, vendor-DB writes, or model dependency. [Phase 1 results](instrument-pull-phase1-20261119.md).

|Mode|Who reads the acquisition directories?|Where are the records?|
|---|---|---|
|Pull|The plugin on amms06, using approved read-only mounts|One local per-instrument SQLite next to the backend. No HTTP hop.|
|Push|The same plugin on the instrument PC, using local directories|One local per-instrument SQLite is also the outbox. The backend receives rows into a local mirror with the same schema. Never sync an open SQLite file over SMB.|

### What the plugins share

Keep stdlib scanner code, SQLite DDL and summary readers together in the portable observer package; the backend uses the same version. No SQLAlchemy, FastAPI or plugin inheritance required on a PC. A plugin reads configured roots with a time/entry/byte budget, returns evidence and its next source cursor, and applies typed evidence to its own tables. Do filesystem I/O before opening a write transaction.

- **One stream per instrument and writer generation.** Each DB identifies instrument, plugin, contract/plugin versions and stream ID. Give every replicated fact, scan or heartbeat a strictly increasing `seq` from **one sequence across tables**. Store evidence, source cursor and sequence advancement atomically. A common event header keyed by seq can be joined to vendor detail; local cursor bookkeeping and derived views need no duplicate seq. An unchanged poll need not emit a row. Keep transitions, selected run/tune/cal changes and occasional heartbeats; bound transient telemetry and never prune unacknowledged push rows.
- **Time and provenance.** `observed_at` is source time when known; `recorded_at` is the writer's UTC clock; backend receipt time is separate and must not overwrite either. Preserve source kind, configured root alias, relative path and position (offset, mtime_ns or fingerprint as applicable). Keep vendor timestamp text/zone assumption when uncertain; leave UTC source time null rather than silently labeling local time UTC. Sequence orders delivery, not physical events. A source-file mtime is not an acquisition-finished timestamp.
- **Two small read contracts:** latest scan/heartbeat (coverage, last successful scan, error, freshness) and latest runs (identity/path, supported state, observed times and evidence), with bounded pagination. Thermo can additionally store verified TNG transitions, reported telemetry, RAW/QC file observations and tune/cal revisions. Bruker starts with `.d` file metadata only. Derive common views from real samples; leave unavailable fields null.

### Registry, delivery and dashboard

**Registry:** keep editable configuration in the main iSPEC DB, not the agent DB or individual archives. Stable instrument ID, display name, plugin, mode, named acquisition/log/tune roots, collector ID, local DB key/path, enabled flag and expected heartbeat interval. Staff can view; admins create/edit via proposed `POST/PATCH /api/instruments` (PATCH by ID). Resolve DB keys under a server-owned directory; restrict source roots to operator-approved locations. No arbitrary filesystem browser, secret, or command in the form. Push adapters read a local manifest; editing the registry does not remotely grant a PC new filesystem access. One active writer per instrument: changing mode/collector explicitly retires the old stream and preserves its history.

**Push:** proposed `POST /api/instruments/{id}/batches` with version, stream ID and contiguous typed rows after the last durable ack. Reuse [collector bearer auth](../src/ispec/instruments/auth.py), collector-to-instrument allowlist and [existing HTTPS/loopback and no-redirect sender](../src/ispec/instruments/collector.py); enforce TLS at the deployed ingress, small byte/row limits, and validate plugin, mode, stream and schema before writing. No general API keys, reads, or control authority from collector credentials. Commit rows and highest contiguous seq together in the mirror; **only then** return the ack. Identical retries return the committed cursor, conflicting same-seq payloads or gaps return 409 with the expected cursor. The PC advances its own cursor only after ack; on uncertain delivery it resends with backoff. A reset/restored PC must reconcile high-water marks or register a new generation, never reuse seq for new data. Keep the v1 single-snapshot route and agent table intact during rollout; mark reads as v1, then retire ingestion per collector after parity. No implicit backfill, double-write, or deletion.

**Staff dashboard:** proposed `GET /api/instruments`, `/{id}/status` and `/{id}/runs` under that prefix. Preserve the existing status response for v1 callers; add a versioned/compatible summary for plugin instruments. Aggregate on request from the registry and local DBs opened read-only, with short timeouts and bounded results. A missing, locked or unsupported DB affects only its card. Show last collector contact, last successful source scan, latest source event and last mirror receipt separately. **Unknown** means insufficient evidence; **stale** qualifies the last known observation; **idle** requires fresh affirmative vendor evidence. A fresh heartbeat, an empty share or a stable file proves none of these instrument states. Late uploads cannot make old acquisitions look current.
